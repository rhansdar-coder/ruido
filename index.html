Access

Six ways in. None of them touch your key.

Ruido is not a wallet and not a mixer. It reads public chain data, and it writes cover through an account you already control. The instrument is its own page; these are the entry points into it.

01Read

Public RPC

The meter is the read path. It pulls the pool's event log from public endpoints, resolves it against every class version the pool has run, and measures the set that survives an adversary. No account, no key, no allowlist — anyone can recompute it and argue with it.

Throwaway key

An apply_actions call can be built and executed against a public RPC with a key that is generated, never funded and never registered. That is how the emitter's interface is verified in this repository. The viewing key travels inside the calldata, so it has to be one you would be willing to publish anyway.

04Order

Commit to a cell

The buyer asks for bits, not decoys, and gets back a quote and two commitments: one to the window, which the provider is given so it can emit in time, and one to the denomination, which it never sees. Splitting them is what makes withholding the amount possible at all — a single commitment cannot open one half without opening the other.

Authnone
Costfree
Statuslive
Entrynpm run quote
05Connect

Buy it from a provider

Cover is a service, not a feature of this page. The buyer's client asks a provider for its terms, prices the order against the ladder the provider actually runs, and sends the order with the window half of the reveal and never the denomination. The provider comes back with an invoice for an amount unique to that order — the pool fee plus a tag derived from the order id, because an ERC-20 transfer carries no memo and a bare transaction hash is a form, not a payment. It reads the receipt and answers with one of four verdicts, and the one that matters is that a chain it cannot read is a refusal, never a hopeful credit. What it learns is the window — that is the position being sold: it knows when, not how much. A book lists who is selling, and it lists offers rather than orders, so a buyer's cell never reaches it.

06Verify

Anyone, after the reveal

The buyer publishes both preimages once the window closes, and anyone can recompute the commitments and count the decoys that landed in the cell. Settlement also refuses to pay twice for the same decoy — windows overlap, so a decoy in one buyer's cell is usually in another's, and without a first-claim rule one batch can be sold to every buyer who asks.

What is deliberately not an entry point

  • No wallet connection. Neither page ever asks for a signature or sends a transaction. The RDO panel is a calculator.
  • No deposit, no custody. Ruido never holds funds and never touches a pool key, so there is no balance sitting here to drain.
  • No mixing. Decoys are ordinary apply_actions calls. The pool does the shielding; Ruido only widens the set you were already hiding in.
  • No API key. Every figure is reproducible from public RPC, so a reader can recompute it without asking us for access.

Questions

Before you trust the number.

What exactly is "effective anonymity"?

The count of notes that are still consistent with everything an adversary knows after they apply it. A pool of 8,322 notes sounds like 13 bits. If the adversary knows the block, 93.4% of notes in the pool we measured have no other candidate origin at all, which is 0.15 bits.

Is the pool broken?

No. The STRK20 pool does what it claims: it hides what a note is worth and who spends it. It does not hide when the note was created, because creation is an on-chain event. At 1.25 notes per thousand blocks, "when" is close to a unique identifier.

Can cover traffic fix this?

Partly, and only in the dimension it targets. Cover raises the candidate count for a timing adversary. It cannot fix a protocol-level leak: if a pool publishes both counterparties when a channel opens, no amount of traffic hides that relationship.

Why is aimed cover so much cheaper than blind cover?

Blind cover spreads decoys across every block and denomination, so most of them land where the adversary is not looking. Measured on 200,000 decoys, 1 in 1,709 lands in the cell that will be searched, against 1 in 7 for window-only and 1 in 1 for aimed. Six decoys in seven land on a rung the adversary does not care about, and of the seventh only 1 in 238 lands in the window — so blind cover is the same product at roughly 1/1,700th the yield.

Between the two aimed positions the gap is the interesting one, and it has an exact answer. For the same anonymity, withholding the denomination costs the ladder width — 7× on a 7-rung ladder — because hiding which rung is yours means emitting all of them. Three bits takes 14 decoys aimed and 95 window-only. At the same budget instead it reads 3.5× at ten decoys, and both numbers are true: they answer different questions. The timing is not a secret a buyer can keep — cover has to land before the spend — so the denomination is the only axis that can be withheld.

Which network is this, and did mainnet change the answer?

Both, and yes — it broke our prediction. We expected mainnet to read worse than Sepolia because a quieter pool has fewer notes to hide among. It reads better: 1.76 bits on mainnet against 0.15 on Sepolia, because mainnet is 4.6× denser at 5.77 notes per thousand blocks versus 1.25. Testnet is not a scaled-down mainnet; it is a different regime, and we were wrong to assume otherwise. Both measurements ship in this repository and the instrument's network switch flips between them.

Is RDO an investment?

No — and it is not issued, so there is nothing to invest in. It would be a fee-discount token for a service: no claim on revenue, no governance rights over the pool, no emissions to holders. Token designs that look like securities are a legal problem, not a feature — read docs/TOKEN.md before treating it as anything else.
